# Phase 9 preregistered inspection specification — 16 October 2026

Recorded before implementing the evaluator. Authority: D2 FR19–FR21, BR07–BR09; D3 UC10/US12–13, §§3.3/3.5/4.5/6.4/6.5/8.3, S10, AT07/AT11; CR-ID-01 and CR-PARTS-01. The user authorizes this bounded implementation and part-schema decisions without another approval round. No expert, physical bench or operational validation is claimed.

## Approved whole-device rules and explicit schema choices

Freeze `TECH-INSPECTION-1.0` with `ASSESS-1.0`. All answers are required; an explicit UNKNOWN is a complete observation, unlike an absent answer. Technician observations are separate from immutable consumer self-reports. All functional tests use PASS/FAIL/UNKNOWN. Only keyboard secondary `power` permits NOT_APPLICABLE, with a mandatory reason; every decisive function remains applicable. This conservative applicability choice prevents absence of test equipment becoming a passing/N/A decisive test.

- Laptop decisive: `power`, `display`, `input`, `system`. Secondary: `enclosure`, `charging_risk`, `connectivity`.
- Desktop decisive: `power`, `system`, `display_input`, `storage`. Secondary: `enclosure`, `ports`, `cooling`.
- Phone decisive: `power_system`, `display_touch`, `charging`. Secondary: `connectivity`, `enclosure`, `battery_risk`.
- Flat-panel monitor decisive: `power`, `image`. Secondary: `enclosure`, `connectors`; no CRT support.
- Printer decisive: `power`, `test_page`, `feed`. Secondary: `connectivity`, `enclosure`, `supplies`.
- Router decisive: `power`, `connectivity`. Secondary: `enclosure`, `ports`; shared data status includes configuration data.
- Keyboard decisive: `input`. Secondary: `enclosure`, `cable`, functional `power` as above.

Shared `safety_concern`, `physical_damage`, and secondary concerns use YES/NO/UNKNOWN (YES means a concern, including connectivity/ports/supplies); `data_status` uses YES/NO/UNKNOWN; `repairability` uses REPAIRABLE/NON_REPAIRABLE/UNDETERMINED. N/A reasons are keyed by question. A private fault/observation reason and private evidence/reference accompany every inspection. Required reason/evidence therefore supports failure repairability; no invented cost/value threshold exists. Inspector, UTC observed/recorded times, current facility/custody, schema/rule versions and immutable rule checksum are frozen.

Apply the first matching approved rule: R01 unsupported/restricted hazard → HOLD; R02 safety UNKNOWN → HOLD; R03 missing/unknown decisive values, inappropriate N/A, conflicts (including all functions PASS plus NON_REPAIRABLE) → HOLD; R04 decisive FAIL + NON_REPAIRABLE + reason/evidence → RECYCLE; R05 decisive FAIL + REPAIRABLE + reason/evidence → REFURBISH; R06 decisive FAIL + UNDETERMINED → HOLD; R07 all applicable decisive tests PASS without safety restriction → REFURBISH; R08 otherwise → HOLD. R08 is the defensive no-condition fallback, not a claim that valid complete current schemas necessarily reach it. UNKNOWN data alone retains an unresolved release gate, not a non-repairability inference. Secondary concern/unknown codes remain visible for later work; they cannot silently clear a safety flag.

Hazard mapping clarification before the additional boundary tests: `charging_risk`, `battery_risk` and SSD `thermal_issue` are explicitly labelled safety concerns. YES supplies R01 even if the shared answer says NO; UNKNOWN supplies a hard manual-review condition under R03 (R02 retains priority if shared safety is UNKNOWN). Expected boundary results are R01/hold and R03/hold respectively. Ordinary connector/enclosure/noise concerns are retained secondary observations, not automatically statutory restrictions. A recorded hard safety/identity/scope restriction persists across later assessments and permits only HOLD decisions; there is no safety-resolution command in this increment.

## Proposed part extension authorized for this increment

Freeze **separate** `PARTS-INSPECTION-1.0` and `PARTS-ASSESS-1.0`, retaining R01–R08 order with these declared subtype predicates. Whole-device ASSESS-1.0 is unchanged.

- HDD and SSD: decisive `detection`, `diagnostics` PASS/FAIL/UNKNOWN; `media_identified` YES/NO/UNKNOWN; `connector_damage` YES/NO/UNKNOWN; HDD `unusual_noise` / SSD `thermal_issue` YES/NO/UNKNOWN. Record only competent, safe device diagnostics/identification; do not browse/copy user files, write destructive test patterns, dismantle or force power-on. Unavailable/unsafe diagnostics stay UNKNOWN. Identity NO is R01; UNKNOWN is R03. Connector/noise/thermal concerns remain explicit secondary observations; actual restriction must be recorded in safety. Data-bearing is server-derived YES permanently, never client editable; success does not sanitize. No parent/removal fields or second storage identity.
- Fan: decisive `rotation` PASS/FAIL/UNKNOWN; `fan_voltage` WITHIN/OUTSIDE/UNKNOWN (≤24 V DC), `fan_size` WITHIN/OUTSIDE/UNKNOWN (≤140 mm largest frame/housing, excluding free leads), `fan_application` ICT/OTHER/UNKNOWN, `fan_electronics` BASIC/ADDITIONAL/UNKNOWN; `unusual_noise` YES/NO/UNKNOWN. BASIC allows factory driver/tachometer/PWM only. OUTSIDE/OTHER/ADDITIONAL is R01; any unknown boundary/electronics is R03. Qualified basic fan data status is NO; otherwise UNKNOWN. These are project scope bounds, not safety certification. An unsafe/unavailable rotation test stays UNKNOWN. No powered measurement instructions.
- Parts retain shared safety/damage/repairability and reason/evidence. No N/A part tests. Safety YES always outranks functional pass/fail; safety UNKNOWN is R02. Additional ambiguous electronics cannot become a non-data-bearing fan by selecting a pathway.

## Decision and preservation contract

Freeze inspection and recommendation together, then require a separate decision for the latest assessment. REFURBISH/RECYCLE/HOLD are pathway decisions, not work/release. Reasons are mandatory for every decision (including divergence). Restricted/unknown safety, unsupported/unknown part identity/scope and existing disputes cannot be overridden; other diagnostic HOLD recommendations may receive a reasoned human pathway decision while retaining all unknown facts and data gates. New inspection clears only the current decision pointer; old decisions stay immutable. No mandatory second person, generic correction, sanitization, repair execution, dismantling, batch or disposal workflow.

Use explicit current facility scope, accepted facility custody and immutable first-receipt/handover proof. Normal receipt/accountability never changes on inspection/decision. Forward guards must admit only complete inspection/decision ledgers, preserve custody event/version, and not invalidate consumed route history. No invented assessments or changes to existing consumer facts during migration. Reauthorize identical retries before returning the original result; never reuse an older decision as current for a newer inspection. No external mail or historical outbox draining. Final browser/bench/integrated acceptance remains deferred.
