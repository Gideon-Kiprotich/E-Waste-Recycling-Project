# Phase 10B media inventory contract

Recorded before application implementation on 16 October 2026. Authority: CR-MEDIA-01 appended to D2/D3 and the user's accepted Phase 10B design. Reuse S10/S11 composition and existing Blade/CSS/feedback; no new Stitch export.

Commands: Record inventory observation (identify new, recognize existing, unresolved), Correct inventory entry, Attest completeness, Authorize media treatment. Each observation/attestation advances the parent's inventory aggregate; authorization has a separate consecutive per-medium aggregate. Treatment does not advance inventory. Any inventory revision invalidates completeness unless it is itself a fresh attestation, and invalidates prior parent authorization. Guide users to identify all media, attest completeness, authorize each derived drive, then record/verify/validate external work. Later inventory revisions need fresh attestation/authorization and legitimate applicability review, not fictitious physical work.

Confirmed entries hold one permanent canonical medium. Resolving an unbound entry retains its entry ID. Correcting an unbound observation to not-present requires evidence/reason. Correcting a bound identity creates a disputed claim, retaining the identity, placement and all destruction concerns. No unlink, merge, reassignment or hidden physical removal exists. A medium can have only one claimed parent; disputed claims remain exclusive pending separately reviewed correction. This deliberate correction limitation must be visible.

Completeness is YES/NO/UNKNOWN; YES requires affirmative identity/count/configuration-storage/access checks and evidence. Missing/inaccessible areas preclude YES. Parent N/A requires current technician NO, zero applicable media, complete inventory and a reason. An empty list does not imply N/A. Parent coverage is one database calculation over current inventory/assessment/custody and all linked canonical media gates. Unknown/unsupported/disputed/failed/stale states block. Destruction concern and coverage are separate; destruction never establishes reuse suitability.

New processor-derived identities use evidenced observed facility control (not first receipt), an immutable origin linking parent/observation and coherent current facility custody. They are not eligible for consumer registration/requests or independent transfer. No parent/media custody movement is supported while linked. Existing standalone origins/identities/assessment requirements are unchanged. Media kinds are hdd/ssd/other_nonvolatile; the latter has no treatment authorization or positive assurance under MEDIA-ASSURANCE-1.0.

New derived treatment records use authorization context 2 and freeze parent assessment/decision, inventory, authorization and media-control versions explicitly. Context 1 retains standalone prerequisites and historical semantics. Both use the original immutable treatment ledger and policy; current applicability is re-evaluated, never inferred from old success.

Acceptance cases M01 identity/reuse/serial unknown/global duplicates; M02 provenance/ownership/coherent control/no fake receipts; M03 versioned unknown resolution/disputed correction/omission; M04 multi-media completeness/NO-N/A/configuration unknown; M05 supported/unsupported authorization; M06 existing assurance and reassessment/revalidation/new failure; M07 permanent destruction concern; M08 concurrency/retries/stale and revocation; M09 forced deferred direct-write/reciprocal enforcement/atomic files; M10 fresh/populated migration preservation; M11 actual browser/mobile/keyboard/screen-reader/inventory acceptance deferred. Preserve the unchanged routing benchmark target and all observed failures.
