## Implementation contracts

- A membership retains the existing single-role/one-account relationship and may link one Collector to one organization. Only Administrator controls create a Collector or link/deactivate an existing Collector; Consumers and other roles cannot be converted. Existing unscoped accounts remain unscoped. Account hashing/password validation are reused; private passwords never enter event/command payloads in plaintext, flashed input or reports. Access changes advance membership/account/session versions, remove stored sessions and invalidate active work. A suspended account cannot be silently reactivated by a scope link.
- Offer and acceptance independently require current Ready review, pickup mode, outstanding owned/reserved registered items, matching current observations, current service area/date/safety facts, active scoped Collector and approved collector/both operator. Operator places and receiving destination must explicitly match every category/subtype. Receiving destinations are active approved facilities/collection points under processor/both organizations; depots are excluded. HDD/SSD data YES is not a collection blocker or sanitization result. Unknown hazards/fan restrictions cannot be overridden. No route-capacity or appointment logic is introduced.
- Offered and Accepted are active. Declined, Withdrawn, Replaced and Invalidated are terminal. Replacement closes the previous assignment and creates a new Offered record in one transaction, requiring fresh acknowledgment. Named Collectors can decline their outstanding offer without granting collection authority; acceptance requires the frozen eligibility binding still to match. Administrative withdrawal resolves stale live assignments without requiring another Ready decision.
- Assignment changes leave reservations and custody untouched. Date/observation/review/directory changes invalidate assignments transactionally. Cancellation invalidates the whole pickup assignment and releases only selected cancelled-item reservations. Access changes invalidate that Collector's work. Directory changes retain Phase 4's conservative invalidation of all outstanding reviews/jobs. Out-of-band drift immediately blocks sensitive reads/acceptance; GET requests do not repair data or append events. Administrators resolve the recorded obligation explicitly.
- Assignment versions are separate from request versions and bind the reviewed request/review snapshot, membership version, operator/place versions and current capability facts. Pure assignment commands do not bump request versions and thus do not invalidate their own Ready review. Existing outcome-derived request headers remain; the separate milestone says **Accepted — not scheduled**.
- Existing advisory transaction gate, actor/session reauthorization, locking, keyed command hashes, retry-first results and append-only event/outbox machinery are reused. Identical authorized retries return the original safe record, including after terminal/replaced outcomes; changed payloads and stale commands conflict. Scope revocation does not permit a retry to restore access. Only the named active-assignment index conflict is converted to the specific allocation conflict; unrelated database failures propagate and roll back.

## Privacy and interfaces

Administrators retain necessary private review access and encrypted allocation/access reasons. Offered Collectors see codes, category/subtype, estimated mass/date preference, relevant safety/data facts, coarse study locality and receiving-place identity. Pickup contact/address/coordinates are decrypted only for Accepted work that is still eligible in the Collector's current operator scope. Closed, replaced, invalidated or drifted work cannot expose those fields; revoked/suspended operator access denies work pages. No serial, owner email/name, private review evidence or unrestricted photo access is added. Consumers see their own safe assignment/operator/destination milestones and never staff reasons. Processors gain no request access in this increment.

Existing Blade layouts, feedback, field associations, pagination and CSS are reused; errors focus the existing summary/link controls. Text is escaped; sensitive pages use private/no-store responses and no-referrer layout metadata. No coordinates enter URLs or persistent browser storage. Error redirects retain only allowlisted command/version/choice references, not passwords, email/display name, private reasons or recovery data; those private inputs must be re-entered. Collector access and allocation forms work without JavaScript. Assignment pages use the approved visual direction, excluding illustrative prototype certification, fleet and acceptance-window claims.

`app:deliver-assignment-notices` consumes only pending in-app outbox rows joined to existing assignment aggregates and six explicitly supported assignment event types. It locks rows with SKIP LOCKED, creates one notification per unique outbox ID and marks delivery in one transaction. Retry cannot duplicate notices; failure leaves the committed domain action intact and delivery pending. Historical non-assignment pending rows are not drained or changed. Recipient-scoped notices/read state contain static safe event summaries/code/time, remain safe after access revocation and link only to pages that reauthorize. There is no email delivery. The scheduler invokes only this bounded command once per minute; README documents a private local one-shot alternative and scheduler setup.
