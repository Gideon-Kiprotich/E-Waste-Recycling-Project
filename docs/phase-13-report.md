## Settled behavior

**Acceptance setup:** Administrator → **Output acceptance profiles** (alongside **Operators and places** and **Place staff access**) reviews an approved in-application facility's exact output type, normalized material specification and explicitly affirmed non-hazardous stream. Normalization folds case and whitespace only; no semantic/material capability is guessed. One permanent profile namespace per facility/type/specification/hazard prevents parallel approval bypass. Scope is immutable; approve/suspend appends review versions. A negative review remains possible for an inactive facility. Device-category capabilities alone are insufficient; canonical storage also requires the exact HDD/SSD capability. Unknown or unsupported streams, external-only recipients, certifications and inferred real operational acceptance are excluded.

**Shipment preparation:** Processor → **Downstream movements** → source batch → **Prepare shipment draft** selects one original output, one reviewed destination and one named current Processor, requested kg and explicit hazard declaration. One output per shipment bounds the first implementation; multiple shipments/partial dispatches are independently traceable. Drafts claim nothing. **Reserve stock** creates an exact claim; **Withdraw remaining reservation** releases only undispatched quantities. No automatic expiry. Profile, directory, membership or measurement changes can stale prior preparation; withdraw remaining reservations and prepare a fresh draft rather than replaying a completed command.

**Actual dispatch and receipt:** **Record actual dispatch** requires current complete reconciled accounting, active source facility scope/capabilities and current matching reviewed destination/recipient. Explicit actual-fact attestation, observed/server-recorded time and private evidence are required. A partial dispatch consumes its reservation portion once; the remainder remains reserved. Source preparation changes require a fresh draft for further reservation/dispatch. A previously dispatched quantity can be acknowledged after legitimate fresh reconciliation without requiring the original preparation record to become current again. Dispatched quantities are in transit with last confirmed sender accountability until the named recipient records the actual outcome.

**Named-recipient inbox → View shipment** exposes only that shipment. **Acknowledge accepted quantity** requires the actual output QR/manual code and separate condition observation. Aggregate partial allocations retain original-lot lineage; acknowledgment transfers only the accepted quantity's control, never the entire retained lot. Damaged material may be physically accepted, with a separate blocking condition discrepancy. **Record refused quantity**, **Record missing quantity**, **Record quantity dispute** and **Record downstream loss** partition the referenced outstanding dispatch. They cannot restore source stock or fabricate a return. Unsupported resolution remains blocked and assigned, rather than represented as a passed acceptance test.

**Exact accounting:** all quantities use existing strict decimal parsing and `numeric(12,3)` kg. Accounted source stock = measured production − actual dispatch − source-stock loss; reservable stock subtracts active reservations. Acknowledgment, completion and downstream loss never deduct source stock again. Existing production IDs are adopted directly; no migration seeds production or movements. Canonical drives are indivisible whole measured outputs, not fractions or duplicate physical subjects. Source-stock loss is limited to actual available aggregate quantities. Loss remains distinct from recovered mass and leaves a blocking exception pending supported review.

**Canonical custody and assurance:** only actually detached canonical HDD/SSD with current satisfied supported assurance can dispatch. A narrow reciprocal accepted-movement chain extends existing custody/origin/route guards without inventing a first receipt or deleting placement/detachment history. Identity, owner, encrypted identifier, original provenance and assurance remain. Source treatment authority becomes stale at dispatch. The named recipient uses **Authorize received-drive applicability review**, then **Media sanitization / applicability review**. Explicit context 4 anchors to the accepted receipt, original detachment/batch/RECYCLE decision and current destination scope. It reuses `media_authorizations`, `sanitization_records` and `sanitization_current` with unchanged MEDIA-ASSURANCE-1.0. Justified prior accepted evidence can be revalidated; no successful work or repeat attempt is fabricated. Failure/destruction concerns remain blocking/non-reusable.

**Completion and closure:** **Record completion evidence** references an accepted quantity, responsible actor/documentary issuer, time and private provenance. Supported recorded outcomes are material/component recovery or disposal, reviewed non-hazardous residue disposal, and controlled canonical storage with current reviewed assurance. Controlled storage accounts for the surviving-media obligation; it is not a reuse release, resale, destruction or claim of recovered material. Evidence remains an accountable assertion, not independently certified proof. **Close accounted batch** requires complete reconciled production, zero source stock/reservations, every dispatched fraction accounted with final evidence, cleared surviving-media obligations and no blocking discrepancy. Balance, dispatch and receipt alone cannot close it. Header status is derived from the ledger; the original on-site processing projection is preserved. Consumers see only their own source association and safe aggregate milestones, not private weights/evidence, other owners or per-device yields.

**Corrections and contradictions:** withdraw affected reservations before ordinary pre-dispatch measurement correction, then append the correction and fresh completeness attestation. After dispatch/source loss, movement-affecting ordinary correction is frozen. **Report measurement or later evidence dispute** retains facts/evidence and blocks progression without rewriting quantities or a historical closure. Subsequent negative/new-execution assurance evidence after closure is exposed as a blocking exception against the frozen closure assurance snapshot. General return, redistribution, ownership transfer, exception resolution and stock correction remain unavailable.

## Role-based walkthroughs — manual acceptance deferred

1. **Administrator:** finish **Operators and places** approval, real declared supported scope and **Place staff access** for source/destination facilities first. Open **Output acceptance profiles**; choose the receiving facility, exact type/material specification and explicit hazard scope; attach private review evidence and **Record output acceptance review**. For drives, separately grant exact HDD/SSD capability. Approval is a prototype declaration, not certification.
2. **Source Processor:** complete Phase 12 actual dismantling, every output measurement and **Attest complete output accounting** within tolerance. Clear applicable supported assurance for every drive to be dispatched. Open **Downstream movements → Open downstream accounting → Prepare shipment draft**. Match the destination profile and named Processor; use the actual output and requested kg. Save the draft, then **Reserve stock**. Only after actual transport activity occurred use **Record actual dispatch**, recording actual kg, time and private evidence. The remaining reservation stays visible after a partial dispatch.
3. **Named receiving Processor:** open **Downstream movements → Named-recipient inbox → View shipment**. Inspect the original output/code, destination and separate quantity totals. Use **Acknowledge accepted quantity**, entering the actual printed EWC code, quantity, condition and evidence; select the original dispatch. Refused/missing/disputed quantities use their separate actions and remain blocked from ordinary closure. There is no automatic physical return or stock restoration.
4. **Received drive:** use **Authorize received-drive applicability review** and all explicit identity/safety/scope checks, then **Media sanitization / applicability review** to revalidate justified prior evidence or record genuine external work with separate verification/validation. Pending/failed/destruction concerns cannot be cleared by uploading a completion document.
5. **Completion:** recipient uses **Record completion evidence** against each accepted fraction with the actual issuer/outcome/evidence. Source Processor checks every output, residual reservation/stock, pending receipt/completion, media obligation and discrepancy, then **Close accounted batch**. Repeat per original output; no second deduction occurs at acknowledgment/completion.
6. **Recovery:** withdraw undispatched reservations before correction or fresh setup review. After actual dispatch/loss, report a measurement/evidence dispute; do not invent balancing material, loss, return, identity or replacement. Missing resolution stays blocked. Later contradictions preserve historical closure while exposing a blocking exception.
