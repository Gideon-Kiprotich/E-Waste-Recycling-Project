## Preparation, eligibility and actual work

**Prepare batch draft → Save draft selection** creates an evidenced preparation record and permanent batch label, with no input reservation, stock claim or authority to dismantle. Current facility-controlled inputs remain unchanged. A draft supports at most 25 selected inputs as a bounded request limit; subsequent selection revisions are retained.

**Record actual dismantling** requires the current human RECYCLE decision for every source, confirmed accepted facility control, active scoped Processor, exact input and HDD/SSD capabilities, complete applicable inventory, coherent ownership/identity and no safety, transfer, pending owner-return or work/return restriction. Eligible whole-device inventory is confirmed separable HDD/SSD or evidenced complete empty inventory with current technician NO; current UNKNOWN, unsupported/inaccessible storage and unresolved/disputed entries block. Qualifying fan inspection must affirm the existing voltage/size/ICT/basic-electronics bounds and technician NO. Standalone-drive dismantling and claimed child-as-intact-input are excluded.

The Processor explicitly attests actual dismantling, actual safe detachment of every displayed canonical drive and identity/safety, with observed/recorded time and private evidence. Creating a batch does not physically perform work. Under locks, commitment freezes decisions/source versions and measured input, creates permanent input membership, exact detachments and reciprocal physical events atomically. Parent items become terminally `dismantled`; custody party/event/version are unchanged. A source cannot join another committed batch or return to intact through ordinary edits. Preparation selection remains available to competing drafts until one valid commitment succeeds.

## Canonical media, provenance and outputs

`batch_detachments` retains source parent, inventory entry/record, canonical medium, original physical/control versions and the actual operation/event. Historical inventory/placement/origin remains immutable. Detachment ends **active embedding** through this separate ledger; retained parent association is not erased or made available for re-parenting. Every confirmed medium must have exactly one matching detachment and one storage output facet. A missing/additional checkbox fails without partial device, event, stock or file effects.

A surviving drive keeps its existing subject/item/storage ID, label, owner, encrypted identifier, original standalone or facility-derived origin, first receipts, custody and assurance. Only its physical subject version advances through a reciprocal detachment event. Recognized standalone drives retain their own origin/receipt/assessment history. No second drive subject, invented receipt or inter-party transfer is created.

Aggregate material/component/residue observations create `output` subjects linked to their batch. Optional individual source is permitted only for an evidenced permanent member; otherwise source lineage is the batch collectively. Mixed-owner lots have no invented individual owner or ownership transfer. Canonical drive outputs instead add a facet to the existing `item` subject. No generic recovered individual fan/component registration or resale is added.

For this on-site-only increment, batch/aggregate-lot facility accountability is projected through the immutable batch facility party; no item owner or fabricated custody receipt/current row is created for an aggregate origin. Current source/media custody remains enforced by the reciprocal ledger. A later physical aggregate transfer requires a separately authorized acknowledged-custody extension; batch creation, balance or label scanning cannot stand in for it.

**Report unexpected media** appends a bounded blocking discrepancy. It creates no medium, parent, owner or guessed provenance and blocks ordinary accounting and new batch treatment. Reviewed resolution of that identity/provenance issue remains missing functionality.

## Measurement, stock and treatment

`batch_records` is immutable operation/measurement history; `dismantling_batches` and `batch_outputs` are consecutive ledger-backed projections. Each output has one production record. First pending measurement and later reasoned corrections point to the current predecessor; superseding a measurement replaces its projected quantity, never adds production. Genuine additional output uses **Record output observation**. Corrections cannot change inputs, physical identities, source lineage, detachment or output production.

Measurements are fixed `numeric(12,3)` kg with encrypted provenance. Application input rejects excess precision, exponents, negative values, units other than kg and invalid gross/tare/net combinations without rounding. Gross/tare needs both non-negative measurements, gross greater than tare, and exact net difference; net-only forbids gross/tare. Unknown input keeps preparation uncommitted. Unknown produced-output mass is null/pending, never measured zero. Database NULL semantics are explicitly guarded as well as application validation.

The live database calculation shows input, measured outputs once each, signed input-minus-output difference, unmeasured count and exact numeric tolerance `max(0.100 kg, input × 0.02)`. This is the approved prototype assumption, not physical recovery evidence. Embedded storage contributes to input only inside its parent; separately measured surviving-drive output is not another input. Honest excessive/negative variance may be recorded and corrected; it blocks reconciliation without creating automatic loss, balancing outputs or yields. Explicit complete-output attestation is separate and becomes stale after new output/measurement observations. Even reconciled on-site accounting remains open processing, with incomplete treatment visible separately.

Recorded on-site stock is each production facet's latest measured quantity; absent mass remains unknown. **No quantity is authorized for future dispatch in this increment**, including balanced batches. Reservation/deduction, dispatch/recipient receipt/completion and final closure are unavailable. No recovered-material or per-device yield percentage is inferred.

**Authorize detached-drive treatment** appends context 3 using existing `media_authorizations` / current projection, freezing the batch/detachment, retained parent RECYCLE decision, medium/control/access versions, explicit media safety checks and exact capability. Old context-2 parent authorization becomes inapplicable on detachment. Existing standalone and embedded history retains its original contexts. `sanitization_records`, `sanitization_current` and MEDIA-ASSURANCE-1.0 remain the single treatment truth. Justified prior accepted evidence can be explicitly revalidated against context 3; no repeat attempt is fabricated. Newer failure wins, destruction concerns persist, unsupported techniques/media and hard restrictions remain blocked. No wiping, diagnostics, dismantling or hardware command is executed.
