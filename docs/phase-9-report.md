## Frozen schemas, evaluation and decisions

Before evaluator code was written, [the inspection specification](evaluation/phase-9-specification.md) and [60 independently expected cases](evaluation/phase-9-cases.json) recorded **42 approved whole-device cases** (seven category/subtypes × six D3 §8.3 families) and **18 part cases** (HDD/SSD/fan × the same families). Expectations were stated from the published table, not generated by the evaluator. Additional predeclared boundaries cover priority, missing/explicit UNKNOWN, permitted/inappropriate N/A, undetermined repairability, unsupported stream, data uncertainty, missing fault support, fan/media boundaries, explicit secondary hazards and defensive R08 fallback. Fixture agreement measures rule conformance, **not professional diagnostic accuracy**.

Whole-device `TECH-INSPECTION-1.0` uses unchanged D3 `ASSESS-1.0` ordered R01–R08 semantics. Part schemas/rules are separately frozen as `PARTS-INSPECTION-1.0` / `PARTS-ASSESS-1.0`; exact questions, values, applicability and added predicates are declared in the specification. Only keyboard secondary power permits N/A, requiring a private reason; all decisive functions remain applicable. Explicit UNKNOWN is valid complete input; absent required answers are validation errors. Secondary battery/charging/thermal safety concerns cannot be contradicted by a shared NO answer: YES is R01; UNKNOWN is hard manual review under R03 unless R02 has priority. These are explicit hazard predicates, not learned diagnoses or economic thresholds.

Inspection freezes answer rows, private N/A/observation reasons, rule version/checksum, result/decisive answers/missing/conflicting codes, actual actor, facility/custody proof, observed UTC time, server recording time and private attachment/reference provenance. Original Consumer self-reports and item data projections are unchanged. HDD/SSD inspection data is always YES; storage facet and item share the original subject, owner, label and custody. Fan data derives NO only for a positively qualified basic fan, otherwise UNKNOWN. Technician facts never prove sanitization or release. Unsafe/unavailable checks stay UNKNOWN; no file-content inspection, destructive diagnostic patterns, disassembly or unsafe power-on instructions exist.

Recording an inspection and deciding are separate commands. A new inspection projects `assessed` and clears the **current decision pointer only**; prior decisions/answers remain historical. REFURBISH/RECYCLE/HOLD decisions require a private reason; divergence retains and explicitly labels the original recommendation. Ordinary diagnostic HOLD may receive a reasoned human decision, retaining unknown/data gates. Hard safety/identity/scope restrictions persist across reassessment and permit only HOLD pending separately authorized correction. No mandatory second person exists; any currently authorized facility Processor can inspect/decide, with the real actor retained.

Old evidence/history links require current scope/custody again.

The existing S10 direction, local CSS, feedback summary, linked field errors, labels and focus script are reused; no notification library, JavaScript or CSS changes. Inspection and decision forms open separately, avoiding duplicate input IDs. Permitted answer selections and valid submission keys survive validation; private reasons, N/A explanations, references, files and protected fields are not flashed. Errors require private evidence/text reselection; stale updates return explicit conflict guidance. All presented text is escaped. Existing responsive tokens/wrapping are reused; HTML assertions are not a visual or accessibility pass.

Private JPEG/PNG/non-active PDF evidence (one file, 5 MiB maximum) uses existing re-encoding/storage/download protections, or encrypted issuer/record reference with an accountable staff assertion, not fetched/independently verified evidence. Decisions reference the frozen inspection evidence. Consumer queries/presentation expose only owned event/time/current-history/pathway milestones, omitting technician identity, observations/reasons, evidence/references, rule checksums and other owners' information.

Assessment notices allowlist only committed `inspection_recorded` / `pathway_decided` steps for the actor/owner, deduplicate by outbox ID, and reauthorize detail links. The bounded command/scheduler never drains unrelated historical rows or sends external mail. Safe old notice text grants no retained private access. Inbox delivery remains unconfigured/unverified.

## Exact-label walkthroughs (manual acceptance still deferred)

1. **Whole device:** Administrator completes **Operators and places** review/capabilities and **Place staff access** for the receiving facility before the normal request review/allocation/receipt/handover journey. Named receiver accepts actual facility items in **Custody handovers**. A current facility Processor opens **Assessments / Inspection → Open inspection and decisions → Record inspection** for a whole device, records the category tests/shared observations, actual UTC time, private reason/evidence, then **Freeze inspection and recommendation**. Inspect first rule/priority, frozen answers, missing/conflicts and data gate. No decision or work starts automatically.
2. **Standalone drive:** accept the individually registered HDD/SSD at a facility explicitly capable of that subtype. Use the same inspection navigation; confirm media identity and safe detection/diagnostic observations, connector/noise/thermal concerns, safety and human repairability. Use UNKNOWN for unavailable/unsafe checks. The page states **Data-bearing: YES — storage medium**; no user files are browsed/copied and no diagnostic success clears sanitization. Freeze and inspect the separately versioned part result; subject/QR/storage identity remains one.
3. **Fan HOLD:** open an eligible fan received through supported custody, then **Record inspection**. Record voltage/size/application/electronics facts from competent observations; UNKNOWN or outside/additional electronics cannot become a qualified ordinary fan by assumption. Freeze explicit unknowns safely; review HOLD and the hard restriction message. **Record pathway decision** permits only **HOLD — retain restriction**, with reason. Do not power/dismantle an unsafe item to fill a field or bypass the restriction.
4. **Human decision:** after freezing an eligible non-hard-held inspection, open **Record pathway decision**, choose REFURBISH/RECYCLE/HOLD, actual UTC decision time and private reason, then **Record human pathway decision**. Inspect the Current decision and override/original-recommendation labels. This establishes no work completion, data clearance, release, dismantling or custody change. Consumer **My devices → device detail → View your assessment milestones** shows only owned safe history.
5. **Reassessment:** open the same subject and **Record reassessment → Freeze inspection and recommendation** with new observations/evidence. Current decision becomes pending; old inspection/decision remain **Historical** with frozen details for authorized staff. Make a fresh separate decision tied to the latest inspection. Retrying a previous successful command returns its old record without restoring it as Current. Earlier hard restrictions remain held pending separate correction; private values/files must be re-entered after validation errors.
